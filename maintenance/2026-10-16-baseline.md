## Issue #1: categorical levels and continuous indicators

**Public evidence:** [report](https://github.com/kim0sun/slca/issues/1) and
[maintainer clarification](https://github.com/kim0sun/slca/issues/1#issuecomment-4154165601).
The issue was closed on 2026-03-30. The discussion distinguishes unsupported
continuous indicators from a categorical example whose sampled columns can have
different observed levels. No code fix or continuous-indicator support is claimed.

**Cause verified in source:** [proc_data](../R/data_encode.R) converts non-factor
inputs to factors based on observed values; explicit factor levels are retained.
[arg_mf](../R/arguments.R) rejects unequal level vectors for corresponding
constrained indicators. Matching counts alone are insufficient when labels or
order differ.

**Deterministic synthetic reproduction:** run after loading this checkout with
`pkgload::load_all(".")`. This reduces the public report to the constraint
precondition, without stochastic optimization or any participant data.

```r
m <- slca(L1[2] ~ x1 + x2, L2[2] ~ y1 + y2,
          L1 ~ L2, constraints = c("L1", "L2"))
dat <- data.frame(x1 = c(1, 2, 3, 1, 2, 3),
                  x2 = c(1, 2, 3, 3, 2, 1),
                  y1 = c(1, 2, 1, 2, 1, 2),
                  y2 = c(1, 2, 3, 1, 2, 3))
check_levels <- function(d) {
  mf <- slca:::proc_data(d, m$model, na.rm = FALSE)
  slca:::arg_mf(m$model, m$arg, mf, fix2zero = NULL)
}
msg <- tryCatch({check_levels(dat); "no error"}, error = conditionMessage)
stopifnot(identical(msg,
  "levels for variables constrained to equal are different"))
dat[] <- lapply(dat, factor, levels = 1:3)
stopifnot(is.list(check_levels(dat)))
```

**Observed:** both assertions passed on the baseline under R 4.5.0. Explicit
matching levels pass this precondition; this tiny example does not establish
convergence, identifiability, or continuous-response support. Internal helpers
are used only to isolate the check, not as a recommended public API.

**Regression/fix status:** existing tests include constrained-model reordering
and simulation level validation, but no dedicated regression for this report's
unequal observed levels. The example above is a verified work record, not an
addition to the automated suite. No package behavior was changed.
